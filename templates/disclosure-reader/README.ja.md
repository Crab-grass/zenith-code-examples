# 開示リーダー（有報の本文・株主・政策保有・自己株式・役員と報酬、臨時報告書を競合で並べるテンプレート）

[English](README.md) · [リポジトリのREADME](../../README.ja.md)

経営企画・IR・調査の担当者向けに、**2〜5社の有価証券報告書の奥の開示**を並べて読むサンプル画面です。数値の表だけでは見えない、リスクの書き方・株主の顔ぶれ・政策保有の整理・監査報酬と販売先・自己株式と議決権・役員の顔ぶれと報酬を、会社ごとの列で比べます。臨時報告書は、提出日の順の年表で並べます。

| 画面 | できること |
| --- | --- |
| 1. 本文の読み比べ | 事業等のリスク・経営方針と対処すべき課題・研究開発活動・設備投資等の概要・監査の状況の**見出しを会社ごとの列に並べる**。キーワード（例：為替・サイバー・人材）がどの見出しに出るかを強調し、見出しを押すと本文を右に出す。見出しと出典だけを入れた「AIに渡すプロンプト」をコピーできる |
| 2. 株主 | 大株主の上位10（共通する大株主・比べる会社自身に印）、所有者別の構成の100%横棒、直近の大量保有報告（1通の報告書を1行。共同保有は合計の割合と内訳） |
| 3. 政策保有 | 純投資目的以外で保有する株式の数、保有中の明細と前期からの増減、**期中に売り切った保有先**、みなし保有株式、子会社が持つ分、比べる会社どうしの**持ち合い** |
| 4. 監査と販売先 | 監査証明業務・非監査業務・同一ネットワークへの報酬と非監査の割合、売上の10%以上を占める主要な販売先と売上高に対する割合 |
| 5. 自己株式と議決権 | 有報の「自己株式等」の表から、**議決権のない株（自己保有株式・相互保有株式）**の株数と発行済株式に対する割合、相互保有株式の行、**前期からの増減**、**決算短信の自己株式数との差**と提出日現在の発行済株式数 |
| 6. 臨時報告書 | 臨時報告書を**提出日の新しい順に1通1行の年表**で並べる（事由が複数ある書類は全部、訂正に印）。**会社×事由の件数の表**と、事由の分類での絞り込み。1通を選ぶと、提出の理由の文の冒頭だけを出し、全文はEDINETの原文へ |
| 7. 役員と報酬 | 有報の「役員の状況」から**役員の人数・男女・女性の比率**（総会後の予定があれば並べる）と、役職名から数えた代表取締役・監査役・監査等委員の人数。「役員の報酬等」から**役員の区分ごとの報酬の総額・員数・1人あたり**と、種類別の内訳（総額に対する割合）、「うち社外」の行、内訳の和と総額の差 |

## 1. 登録不要で試す

必要なものは**Python 3.9以上とブラウザ**です。追加パッケージやビルド作業はありません。

```sh
git clone https://github.com/Crab-grass/zenith-code-examples.git
cd zenith-code-examples
python3 templates/disclosure-reader/server.py
```

**http://127.0.0.1:8790** をブラウザで開きます。終了するときは端末で **Ctrl+C**。ポートが使用中なら `--port 8791` のように変更できます。

保存データは、画面に表示された取得日に **ZENITH Code の実データを取得して保存したもの** です（トヨタ自動車・デンソー・本田技研工業・マツダ・テイン）。最新の開示ではありません。保存データではAPIを呼ばず、登録も不要です。

自動車部品の5社（デンソー・アイシン・トヨタ紡織・武蔵精密工業・エフ・シー・シー）の保存データもあります。主要な販売先（自動車会社）を並べるときは、こちらで起動します。

```sh
python3 templates/disclosure-reader/server.py --demo suppliers
```

- 上の「比べる会社」で2〜5社を選びます。左の7つの画面を切り替えます。
- JA / EN、明るい表示 / 暗い表示を切り替えられます（初期値はOSの設定に従います）。
- `?companies=7203,7261#cross` のようにURLで会社と画面を指定できます。

## 2. 実際のデータに接続する

[会員登録](https://zenithcode.net/sign-up)後、適用される規約・データ利用条件に同意し、ダッシュボードでAPIキーを作成します。次のコマンドで起動し直します。

```sh
python3 templates/disclosure-reader/server.py --live
```

端末の非表示入力でキーを設定します。環境変数 `ZENITH_API_KEY` に設定済みならそちらを使います。`.env` は自動では読み込みません。**キーはブラウザへ送らず、ローカルのPythonプロセスだけが保持します。**

「ライブ取得」を選び、証券コードを2〜5社追加して「取得」を押します。

| 1社ごとのAPI | リクエスト数 |
| --- | --- |
| `/stable/profile`（社名だけ使う） | 1 |
| `/stable/text-blocks?tag=risks` ・`policy` ・`rnd` ・`capex` ・`audits` | 5 |
| `/stable/major-shareholders` | 1 |
| `/stable/shareholder-categories` | 1 |
| `/stable/large-holders` | 1 |
| `/stable/cross-shareholdings` | 1 |
| `/stable/audit-fees` | 1 |
| `/stable/main-customers` | 1 |
| `/stable/income-statement?period=annual&limit=3`（主要な販売先がある会社だけ。売上高と期だけ使う） | 0〜1 |
| `/stable/treasury-shares`（最新の有報と、その1年前の期の有報の2回。最新が404なら1回） | 1〜2 |
| `/stable/extraordinary-reports?limit=50`（新しい50通まで） | 1 |
| `/stable/extraordinary-report-reasons`（事由の一覧。会社の数によらず取得ごとに1回） | 取得ごとに1 |
| `/stable/directors`（最新の有報の役員の状況） | 1 |
| `/stable/director-compensation`（最新の有報の役員の報酬等） | 1 |

**取得 = 1社あたり17〜18リクエスト＋1**。5社なら最大91リクエストです。1社ずつ順番に取得し、並列には呼びません。404（その開示がない）は「なし」として扱い、それ以外の失敗が1件でもあれば全体を中止して途中までの結果は表示しません。リトライ・自動更新はしません。画面の切り替え・キーワード・プロンプトのコピーではAPIを呼びません。

## ブラウザに渡すデータ

ローカルのサーバーが、画面に必要な項目だけを選んでブラウザに渡します（`server.py` の許可リスト）。

- **株価や株価から計算する指標は渡しません。** `/profile` の株価・時価総額・PER・PBR・配当利回りなどは取り除き、社名だけを残します。
- **政策保有株式の貸借対照表計上額（`carryingAmount`・`priorCarryingAmount`）は渡しません。** 上場株式は時価で計上されるため、株価から決まる値だからです。株数・保有の目的と理由・相手の保有の有無だけを使います。
- **損益計算書は売上高と決算期だけ**を渡します（主要な販売先の割合の計算用）。
- **自己株式等の表は、所有者の名前と株数・割合だけ**を渡します（住所と英訳は渡しません）。決算短信の株数（`consolidated`）は期・発行済株式数・自己株式数の数字だけで、書類へのリンクはありません。
- **臨時報告書は、書類ID・書類の種類・提出日時・事由（key・名前・分類）と、提出の理由の文の冒頭（最初の1文・120字まで）だけ**を渡します。代表取締役の異動などの文には氏名・生年月日・略歴が書かれるため、文の全文（`reasonText`）と構造化した本文（`sections`）は渡しません。代表取締役の異動・主要株主の異動の書類と、生年月日や略歴を含む文は、冒頭も渡しません。
- **役員は、男女別の人数（提出日現在と総会後の予定）と、各行の区分（`group`）・役職名だけ**を渡します。氏名・生年月日・任期・所有株式数・略歴と、総会後の予定の役員の一覧（`plannedOfficers`）は渡しません。**役員の報酬は、役員区分ごとの員数・総額・種類別の額・会社独自の列・小計だけ**で、連結報酬等が1億円以上の役員の氏名と個別の額（`individuals`）は渡しません。
- **TDnet の書類リンクは渡しません。** `archiveUrl` は常に取り除き、`sourceUrl` は EDINET の閲覧ページだけ残します。書類IDと提出日は表示します。
- 大株主の住所は**都道府県（海外は「海外」）**にしてから渡します。
- API側のエラー内容は画面に出しません。

## 読み方の注意

- **見出し**は本文の行頭の「（１）」「①」「1.」「ⅰ)」「a.」「【…】」「＜…＞」「■」などから取り出します（`model.mjs` の `extractHeadings`）。最初に使われた記号が大見出し、その中で新しく出た記号が一段下の見出しです。同じ見出しが3回以上くり返すもの（「＜リスク＞」「＜対応策＞」など）は見出しとして扱いません。文で終わる行（。で終わる行）も見出しにしません。
- **文字数**は受け取った本文の文字数です（APIの `chars` ではありません）。表は文字に並べ直されているため、書類の分量そのものではありません。
- ETF・REIT など、節そのものがない会社は「この節はありません」と表示します。
- **共通する大株主**は、㈱・株式会社・（相）・（信託口）・全角半角の違いをそろえて名前で照合します。同じ信託銀行の信託口は1つにまとめます。
- **大量保有報告**は、1通の報告書（書類 ID）を1行にします。共同保有の報告は、共同保有者が1者ずつ別の行で返るので、保有割合の大きい1者の名前と、共同保有者の合計の割合（`groupRatio`）を出し、内訳を3者まで並べます。名前・株数・割合が同じ報告書（訂正など）は1件にまとめ、新しい順に5件まで出します。新規・変更の別（`reportKind`）も出します。
- **政策保有の明細は開示されている分だけ**です。銀行などは上位60社までの開示なので、明細の行数が保有先の数より少なくても誤りではありません。当期の株数がなく前期だけある行は「期中に売却し保有なし」として別に数えます。持ち合いは、保有先の名前と比べる会社の社名を照合して判定します。
- **監査報酬**は、連結子会社がない会社では合計が空のため提出会社の値を合計にします。非監査の割合は 非監査業務 ÷（監査証明業務＋非監査業務）をこの画面で計算し、非監査業務がなければ0%です。
- **主要な販売先の割合**は、同じ決算期の年間の売上高で割ります。前期の行は12か月前の期の売上高がある場合だけ割ります。割合が100%を超える行は、単位が原文と合わない可能性があるため金額も割合も表示しません。顧客名を書いていない会社（「顧客グループが1グループ」や、2グループの合計額だけの会社）も、金額・期・セグメントの行が返り、名前の欄に「顧客名の記載なし」か「複数の顧客グループの合計」と、理由（API の `notes`）を出します。404 は「API が販売先の行を返さなかった」で、売上の10%以上の販売先の記載がない会社のほか、有価証券報告書がない会社（上場したばかりの会社・TOKYO PRO Market など）や、金額が幅でしか書かれていない会社も 404 になります。依存度を判断する前に原文で確かめます。売上高が空の会社（売上を事業収益で開示する会社など）は割合を出しません。
- **自己株式等**は有報の「議決権の状況」の表で、議決権のない株を並べたものです（会社法308条）。名前が自社の行を**自己保有**、それ以外の行を**相互保有**（この会社が議決権の4分の1以上を持つ会社などが持つ株）として足します（`model.mjs` の `treasuryRows`）。名前の後ろの「(注)１」などは外して照合し、「当社」の行も自己保有とします。割合は 株数 ÷ 期末の発行済株式総数（種類株を含む）をこの画面で計算し、原文の割合も並べます。行の和が「計」と合わない会社、自社の行が名前で見つからない会社は印を出します。表は単元で数えるので、単元未満の自己株式は入りません。
- **決算短信の自己株式数**は連結の数で、有報の表の自己保有とは対象が違います。この画面は差（短信−表）を並べるだけで、**発行済株式から自己株式を引いた数は出しません。** 差が単元未満より大きい会社は原文の注記で確かめます。期末後に株式を分割した会社は、短信の株数が分割後の数になっていることがあります。
- **前期からの増減**は、1年前の決算期の有報の同じ表との差です（`treasuryChange`）。決算期を変えた会社など、1年前の期の有報がない会社は「—」です。
- **臨時報告書の提出日**は日本時間の日付です（APIはUTCで返します。`jstDate`）。件数の表（`extraordinaryCounts`）は、訂正の臨時報告書（書類の種類 190）を除いて数え、訂正は別の行に数えます。1通に事由が複数ある書類は、それぞれの事由に1件ずつ数えます。分類は事由の一覧の `category` で、一覧にない事由は「その他」です。1社あたり新しい50通までを取得し、50通に達した会社は期間の横に印を出します。臨時報告書がない会社は、APIが空の配列を返します（404ではありません）。
- **役員の人数と男女**は、有報の「役員の状況」の提出日現在の数（APIの `counts`）です。女性の比率はこの画面で 女性÷（男性＋女性） を計算し、有報の記載の比率（`femaleRatio`）も並べます。総会後の予定（`plannedCounts`）は、有報が予定の一覧を載せた会社だけです。**代表取締役・監査役・監査等委員・監査委員の人数は役職名の言葉で数えたもの**で、機関設計も役職名から判断します（`officerSummary`）。社外役員かどうかは役職名に書かれないため数えません。指名委員会等設置会社では、取締役と執行役を兼ねる人が両方の一覧に出るので、行の数と人数を比べません。
- **役員の報酬**は、有報の役員区分ごとの表のとおりの行です（`compensationRows`）。1人あたり＝総額÷員数で、員数には期中に退任した人も入ります。員数がない区分は「—」です。**「うち」の行（`ofWhichParent`）は上の区分の内数**なので足さず、会社の合計も出しません（「うち」の印がない社外の行もあるため）。内訳の和＝種類別の額＋会社独自の列（`components`）−小計（`subtotals`）で、総額との差を出します。表は百万円単位で丸めてあるので、差が2百万円以内は丸めの範囲として表示します。どの種類が業績連動かは会社の表の見出しで違うため、業績連動の割合は計算しません。
- 未開示・未取得は「—」と表示し、0 としては扱いません。

## AIに渡すプロンプト

「本文の読み比べ」の「AIに渡すプロンプトをコピー」は、選んだ節の名前・各社の見出しの一覧（キーワードが出る見出しに★）・出典（書類ID・提出日・EDINETのURL）を、指示文と一緒にクリップボードへ写します。**本文そのものは写しません。** 本文はAIにEDINETの原文で確かめさせるか、自分で読んでください。

## 保存データを取り直す

`demo.json` と `demo-suppliers.json` は、実データ接続と同じ関数（`server.py` の `fetch_bundle`）の出力をそのまま保存したものです。

```sh
python3 templates/disclosure-reader/build_demo.py                   # demo.json（7203 6902 7267 7261 7217）
python3 templates/disclosure-reader/build_demo.py --set suppliers   # demo-suppliers.json（6902 7259 3116 7220 7296）
python3 templates/disclosure-reader/build_demo.py 6758 6752         # 別の組み合わせを demo.json に
```

キーは `ZENITH_API_KEY` か非表示入力で渡し、コマンドラインには書きません。すべて成功したときだけファイルを書き換え、書き込む前に株価・計上額・TDnetのリンクが入っていないことをもう一度確かめます。

## カスタマイズ

| ファイル | 役割 |
| --- | --- |
| `server.py` | ループバック専用サーバー、項目の許可リスト、`fetch_bundle` |
| `build_demo.py` | 実データから `demo.json` を作る |
| `model.mjs` | 応答の検証、見出しの取り出し、キーワード、名前の照合、持ち合い、売却の数え方、監査報酬、販売先の割合、自己株式等、臨時報告書の年表と件数、役員の集計と報酬の行（Nodeのテストと共通） |
| `app.mjs` | 7つの画面（`VIEWS` に並べる）、会社の選択 |
| `i18n.mjs` | 日英の文言 |
| `index.html` / `style.css` | レイアウト、明るい表示と暗い表示 |
| `demo.json` / `demo-suppliers.json` | オフライン用に保存したデータ（自動車会社 / 自動車部品。`--demo` で選ぶ） |

読みたい節を足すときは、`server.py` の `SECTIONS` と `model.mjs` の `SECTIONS`、`i18n.mjs` の `sec_<名前>` を足します（1社あたりのリクエストが1件増えます）。

ブラウザから任意のURLへ取得させることはできません。サーバーは Host・Origin・起動ごとのトークンを確認し、実データの取得は同時に1つだけ受け付けます。**1人で使うローカル用のテンプレート**で、インターネットに公開する用途や複数ユーザーでの利用は想定していません。
